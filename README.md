# Росток — Игровое банковское приложение

Документ описывает **текущую** реализацию продукта. Формулы и потоки сверены с кодом api-server / bank-game. Имена файлов вроде `economy-v2-*` / `economy-v3-*` — это пути в репозитории; ниже «модель» — то, как игра работает при включённом флаге корней.

```
ENABLE_ECONOMY_V3_ROOTS=true
```

---

## 1. Project overview

### Что такое Росток

**Росток** — игровой клиент (`artifacts/bank-game`) и API (`artifacts/api-server`) поверх **демо-накопительного счёта**. Игрок ухаживает за виртуальным деревом: копится энергия, проходятся мини-игры, завершается цикл **ухода**, начисляются опыт, рост дерева и денежный доход.

Целевая идея для банка: игровой слой над реальным вкладом (Open Banking). В репозитории сейчас — **демо**: регистрация email/пароль, стартовый капитал **100 000 ₽**.

### Игровая идея

Как Duolingo для накоплений: ежедневный ритуал вместо «забыл про вклад». Открыл приложение → забрал энергию из корней → прошёл три мини-игры → нажал **«Уход»** → увидел рост дерева и доход.

### Дерево и экономика — связь, но не прямой перевод денег

| Слой | Что это | От чего зависит |
|------|---------|-----------------|
| **Финансовый** | ₽ на счёте (сейф / сундук), доход за уход | капитал в сундуке, финансовое время, навык, Freshness |
| **Игровой** | энергия, корни, мини-игры, Метёлка | реальное время, ёмкость, действия игрока |
| **Рост дерева** | миллиметры и стадии (росток → могучее дерево) | пресеты активностей, навык, коэффициенты ухода — **не сумма ₽** |

Капитал **ускоряет** накопление энергии и участвует в **денежном** доходе. Высота дерева (**мм**) считается **отдельной** формулой: рубли в `Growth_mm` **не входят**. Дерево — видимый прогресс привычки ухаживать, а не курсор баланса.

## 2. Economy model (текущий поток)

Общая модель — одна цепочка. Каждый следующий шаг потребляет результат предыдущего.

```
Capital
  ↓
Financial time
  ↓
Energy generation
  ↓
Root storage
  ↓
Care activities
  ↓
Tree growth (+ денежный доход и XP при «Уход»)
```

### Роль каждого элемента

| Этап | Роль простыми словами |
|------|------------------------|
| **Capital** | Деньги демо-счёта. В **сейфе** — «не в игре» (медленная колба). В **сундуке дерева** — в игре: ускоряет энергию и базу ₽-дохода. |
| **Financial time** | Сколько «игровых секунд» энергии набежало за реальное время при данном капитале. Связка: `T(K)` и elapsed. |
| **Energy generation** | Непрерывная генерация энергии в реальном времени. Чем больше капитал в сундуке, тем быстрее (с затуханием). |
| **Root storage** | Три корня (Полив / Свет / Удобрение) копят энергию ячейками; игрок **собирает** их в запасы кнопок. |
| **Care activities** | Три мини-игры на запасах; все три → кнопка **«Уход»**; сервер фиксирует навык, XP, ₽, мм. |
| **Tree growth** | Начисление **мм** и смена стадии дерева. Параллельно — денежный доход и XP (отдельные формулы). |

Если обычная ёмкость заполнена, часть генерации уходит в **Excess**; тогда перед обычным уходом нужна **Metelka** (Метёлка).

### Скорость энергии `T(K)`

```
T(K) = 3600 / (1 + 4 · (K / 100000)^0.15)
```

`T(K)` — сколько **реальных секунд** нужно на **1 игровую секунду** энергии. `K` — капитал в сундуке.

| Капитал K | Пример T(K) |
|-----------|-------------|
| 0 ₽ | ~60 мин |
| 100 000 ₽ | ~12 мин |
| больше | быстрее (с затуханием) |

### Разделение: финансы vs игра vs рост

```
                    ┌─────────────────────────┐
  Capital (сундук) ─► Financial time / T(K)   │──► Energy → Roots → Activities
                    │                         │              │
                    └──────────────► ₽ income ◄──────────────┘ (навык, Freshness)
                                              │
  Activities (пресеты + навык) ───────────────┴──► Growth mm  (без ₽ в формуле)
```

## 3. Glossary

| Термин | Простыми словами |
|--------|------------------|
| **Capital** | Деньги на демо-счёте. **Сейф** — вне игры; **сундук** — в игре (ускоряет энергию и доход). Старт: 100 000 ₽. |
| **Financial time** | Игровое время, выведенное из реального через `T(K)`: сколько энергии «заработало» время при данном капитале. Также влияет на расчёт ₽ за уход. |
| **Energy** | Игровой ресурс в секундах. Копится сам, пока идёт время. Нужен, чтобы наполнять корни и запускать мини-игры. |
| **Roots** | Три хранилища энергии под деревом (Полив / Свет / Удобрение). Наполнились → игрок переносит в запасы кнопок. |
| **Care** | Цикл ухода: три мини-игры + кнопка **«Уход»**. На сервере: finish → claim → acknowledge. Даёт XP, ₽, мм. |
| **Metelka** | Мини-активность «Метёлка» (уборка паутины), когда накопился избыток. Пока не пройдена, обычный уход может быть заблокирован. |
| **Excess** | Избыток энергии сверх обычной ёмкости корней/запасов. Ведётся отдельно; открывает путь Метёлки. |
| **Growth mm** | Миллиметры роста дерева. Копятся по формуле ухода; пороги стадий: 0 / 50 / 200 / 500 / 850 мм. **Не** равны «столько-то рублей = столько-то мм». |

**Смежные термины**

| Термин | Значение |
|--------|----------|
| **Skill** | Качество мини-игры 0…1 (в UI часто 0–100%). Влияет на XP, бонус ₽ и мм. |
| **Freshness** | 0.50–1.00; влияет на бонусный % дохода за уход. |
| **Preset** | Длительность активности в игровых секундах (обычно 5–25 с). |
| **Reserve** | Запас на кнопке активности после сбора корня. |

## 4. Economy v2 vs v3

В коде соседствуют модули `economy-v2-*` и `economy-v3-*`. Для нового разработчика важно: **продуктовый путь игрока сейчас — корни + сейф/сундук + Метёлка + отдельный рост мм** (включается `ENABLE_ECONOMY_V3_ROOTS=true`). Модули «v2» часто остаются **общими кирпичами** (например `T(K)`, доход Care, куски excess).

### Какие идеи были в v2

- Непрерывная энергия через **`T(K)`** (не «сессия раз в N часов» как в совсем ранних набросках продукта).
- Банк/ёмкость энергии и переполнение в **excess**.
- Цикл **Care**: три активности → доход **12% + бонус до 3%** с Freshness.
- XP за активности: `round(100 × T / 25 × Skill)`.
- Общие хелперы excess / financial elapsed, которые v3 **переиспользует**.

### Что изменилось в текущей (v3) модели корней

| Было / проще в v2-слое | Стало в модели корней |
|------------------------|------------------------|
| Более общий банк энергии / корни без жёсткой продуктовой схемы «сейф → сундук → три корня → Метёлка» | Явные **три корня + запасы**, перенос капитала **сейф ↔ сундук** |
| Рост дерева не был выделен как отдельный SoT без капитала | **`Growth_mm = T × Skill × Care × LongCare`**, капитал в мм **не входит** |
| Excess как переполнение ёмкости | Excess + продуктовый гейт **Метёлка** (корни/запасы полные) |
| Care finish на клиентских/смешанных допущениях | Серверный пайплайн **finish-cycle → claim-cycle → acknowledge-cycle** |

### Какие системы разделены

| Система | Отвечает за | Главные файлы (ориентир) |
|---------|-------------|---------------------------|
| Скорость энергии / financial time | `T(K)`, генерация | `economy-v2.ts` |
| Хранение энергии | корни, запасы, settle | `economy-v3-roots.ts`, capacity/excess-gate |
| Капитал | сейф / сундук | `economy-v3-capital-vault.ts` |
| Уход (игры + claim) | активности, ₽, XP | `economy-v3-care-*.ts`, `economy-v2-care-income.ts`, `economy-v2-care-xp.ts` |
| Избыток / Метёлка | excess ledger, метёлка | `economy-v3-excess-gate.ts`, `economy-v3-metelka-cycle.ts` |
| Рост дерева | мм | `economy-v3-tree-growth.ts` |

Итог: **деньги**, **энергия/корни** и **мм дерева** — разные контуры с разными входами; путать «баланс вырос → дерево выросло на ту же величину» нельзя.

## 5. Internal mechanics

### API-first

- Клиент **не** является источником истины по балансу, энергии, мм и наградам.
- Состояние читается и меняется через `/api/game/...` (cookie-сессия).
- Vite proxy: `/api` → `http://localhost:8080`.

### PostgreSQL — источник истины

- Игровое состояние в PostgreSQL (raw `pg` на api-server; часть shared-схемы через Drizzle).
- Типичные сущности: `users`, `accounts` (сейф / активный капитал), `game_state` (туториал, XP, `tree_growth_mm`), журналы дохода, колонки корней / Care / Метёлки (миграции на сервере).

### Сервер считает награды

При завершении ухода сервер считает и пишет:

- денежный доход (база + бонус);
- XP;
- **мм** роста (`economy-v3-tree-growth`);
- статусы цикла Care / Метёлки.

Клиент **не** должен «додумывать» финальные ₽/мм локально как SoT.

### Клиент — визуализация и ввод

- Сцена, анимации (XP → рост → монеты/яблоки), туториальные оверлеи, мини-игры.
- Отправляет действия (сбор корня, старт/финиш активности, «Уход», Метёлка) и показывает ответ сервера.

```
Player input  →  API  →  PostgreSQL + services
                              ↓
                         JSON state
                              ↓
                    Client animations / UI
```

## 6. Player lifecycle

Путь нового игрока (как в продукте сейчас):

```
registration
  → onboarding (демо-счёт 100 000 ₽)
  → tutorial
  → capital          (посадить росток → перенести капитал в сундук)
  → energy           (колба / ожидание / ускорение в туториале)
  → roots            (собрать три корня)
  → activities       (Полив → Свет → Удобрение, порядок свободный)
  → care             (кнопка «Уход»)
  → reward           (XP, ₽, ритуал сбора)
  → tree growth      (+N мм, стадии)
```

После туториала тот же цикл повторяется в основной игре; при полном заполнении вклинивается **Excess → Metelka**.

### Туториал (кратко)

| Шаг | Что видит игрок |
|-----|-----------------|
| welcome | план «Ухаживайте за деревом» |
| посадка | «Посадите росток» |
| капитал | энергия без капитала → перенос в сундук |
| энергия | ускорение / ожидание колбы |
| корни | «Соберите энергию из корней» |
| активности | «Пройдите активность» |
| «Уход» | «Нажмите на кнопку «Уход»» |
| награда | «Соберите награду» |
| complete | «Начать играть» → `tutorial_done` |

## 8. Игровые механики подробнее

### Капитал: сейф и сундук

- **Сейф** — капитал не ускоряет колбу как «в игре».
- **Сундук** — капитал в игре.
- Туториал: перетаскивание кошелька из сейфа в сундук.

### Корни и запасы

- Три корня, ячейки по 5 с.
- Сбор в запасы кнопок; пока корни не собраны — уход ограничен.
- Ёмкость: пресет (часто 5–25 с) + бонус серии визитов; корень + запас ≤ эффективный пресет.

### Три мини-игры

| Активность | Компонент | Суть |
|------------|-----------|------|
| Полив | `FallingGameWater` | ловить капли |
| Свет | `ClickGameSun` | тапать лучи |
| Удобрение | `FertilizerMatchGame` | гранулы в ряд |

После третьей кнопки сходятся в **«Уход»**.

### Награды за «Уход»

Очередь на клиенте: **XP → рост мм → ритуал монет/яблок → ₽ в сундук**.

**Денежный доход (сервер):**

- база: `D_base = capital × 0.12 × elapsed / SECONDS_PER_YEAR`
- бонус: `bonusRate = 0.015 + 0.015 × Skill_cycle × Freshness` ∈ [0.015, 0.03]

Ставки **тестовые**.

**Рост мм (сервер):**

```
Growth_mm = T × Skill × Care × LongCare   (floor)
```

- `T` — сумма трёх пресетов (15…75)
- `Skill` — среднее навыков; при 0 → всё равно **1 мм** за завершённый цикл
- `Care` — среднее `C(t) = 1.25 − 0.01t` по пресетам
- `LongCare = 1 + 0.5(1 − e^(−0.01N))` ∈ [1.00, 1.50)

**Стадии дерева:** Росток 0 → Саженец 50 → Деревце 200 → Молодое 500 → Могучее 850+ мм.

### Метёлка и excess

1. Ёмкость полная → генерация в **excess**.  
2. Карта **Метёлка**.  
3. После прохождения — награда, снова обычный цикл ухода.

## 9. Зачем продукт банкам и клиентам

**Клиентам:** ритуал вместо забытого вклада; видимый прогресс (дерево, мм, уровень, капитал).

**Банкам:** дольше держат средства; ежедневное внимание; лояльность.

**Партнёрство (цель):** OAuth / Open Banking к реальному счёту. В коде сейчас — демо-счёт.
