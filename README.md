# Росток — Игровое банковское приложение

## Концепция продукта

### Что такое Росток?

Росток — игровой интерфейс поверх накопительного счёта (сейчас — демо-счёт). Приложение превращает ежедневный уход за капиталом в игру: вы ухаживаете за виртуальным деревом, копите игровую энергию, проходите мини-игры и видите, как дерево и капитал растут вместе.

Идея: **Duolingo в мире накопительных счетов.** Вы открываете приложение не потому что «надо», а потому что интересно забрать энергию, пройти уход и посмотреть прирост.

В результате формируется финансовая дисциплина: привычка заглядывать к вкладу, не снимать накопленное и следить за прогрессом.

---

### Как устроена игра сейчас (Economy v3)

Главный цикл — не «сессия раз в 8 часов», а **непрерывное накопление энергии** и циклы **ухода (Care)**.

```
Капитал в сундуке ускоряет колбу (T(K))
  → энергия копится в трёх корнях (Полив / Свет / Удобрение)
  → игрок собирает корни в запасы кнопок
  → три мини-игры (в любом порядке)
  → кнопки сходятся в «Уход»
  → награда: XP → рост дерева (мм) → монеты / ритуал сбора → ₽ в сундук
```

Если корни заполнены и копится **избыток**, сначала нужно пройти **Метёлку**, затем обычный уход.

Продуктовый путь включается флагом `ENABLE_ECONOMY_V3_ROOTS=true` на api-server. Без флага клиент не получает `game.v3Roots` (legacy-режим).

---

### Капитал: сейф и сундук

- **Сейф** — капитал «не в игре». Колба красная: энергия копится базовым (медленным) временем.
- **Сундук дерева** — капитал в игре. Ускоряет накопление энергии и участвует в денежном доходе за уход.
- Старт демо-счёта: **100 000 ₽** (онбординг «Открыть демо-счёт»).
- В туториале игрок перетаскивает кошелёк из сейфа в сундук.

---

### Энергия, колба и корни

Энергия генерируется в реальном времени. Скорость зависит от капитала в сундуке:

```
T(K) = 3600 / (1 + 4 · (K / 100000)^0.15)
```

`T(K)` — сколько **реальных секунд** нужно на **1 игровую секунду** энергии.

| Капитал K | Пример T(K) |
|-----------|-------------|
| 0 ₽ | ~60 мин |
| 100 000 ₽ | ~12 мин |
| больше | быстрее (с затуханием) |

Энергия наполняет три **корня** (ячейки по 5 с): Полив, Свет, Удобрение. Игрок **собирает** готовые корни в запасы кнопок активностей. Пока не собраны нужные корни, старт ухода заблокирован.

Ёмкость корней/запаса ограничена пресетом (обычно 5–25 с на активность, плюс бонус серии визитов). Общий пул: корень + запас ≤ эффективный пресет.

---

### Три мини-игры ухода

Можно проходить в любом порядке. Все три нужны, чтобы появилась кнопка **«Уход»**.

- 💧 **Полив** (`FallingGameWater`) — ловить падающие капли корзиной. Чем выше доля попаданий, тем лучше навык.
- ☀️ **Свет** (`ClickGameSun`) — нажимать на солнечные лучи, пока есть время.
- 🌿 **Удобрение** (`FertilizerMatchGame`) — собирать гранулы в ряд. Чем длиннее серии, тем выше очки.

Результат каждой активности — **навык (skill) 0…1** (в UI часто 0–100%). Средний навык цикла влияет на XP, рост дерева и бонусный доход.

После третьей активности кнопки плавно сходятся в лопату **«Уход»**. Нажатие запускает серверный пайплайн: `finish-cycle` → `claim-cycle` → `acknowledge-cycle`.

---

### Награды за «Уход»

Типичная очередь на клиенте:

1. вспышка **XP**
2. анимация **роста дерева** (+N мм)
3. ритуал сбора **монет / яблок** (перенос к сундуку / счётчикам)
4. деньги оседают в капитале сундука

**Денежный доход (Care):**

- база: **12% годовых** от капитала в сундуке за финансовое elapsed цикла  
  `D_base = capital × 0.12 × elapsed / SECONDS_PER_YEAR`
- бонус: **1.5%…3% годовых** от навыка цикла и **Freshness** (0.50–1.00)  
  `bonusRate = 0.015 + 0.015 × Skill_cycle × Freshness`

Финансовое elapsed для денег считается через пресеты активностей и `T(K)` (капитал ускоряет не только колбу, но и «вес» времени дохода).

> Ставки 12% + до +3% — **тестовые**, для демонстрации механики. В боевой версии их предполагается привязать к условиям банка-партнёра.

**Рост дерева (мм)** — отдельная формула, капитал в неё **не входит**:

```
Growth_mm = T × Skill × Care × LongCare   (floor)
```

- `T` — сумма трёх пресетов (15…75 с)
- `Skill` — среднее трёх навыков [0, 1]; при Skill = 0 за завершённый цикл всё равно **1 мм** (участие)
- `Care` — среднее `C(t) = 1.25 − 0.01t` по каждому пресету (5→1.20 … 25→1.00)
- `LongCare = 1 + 0.5(1 − e^(−0.01N))` ∈ [1.00, 1.50), N — число успешных уходов за жизнь аккаунта

В туториале рост мм — демо-значение; продакшен-формула применяется к обычным циклам Care.

---

### Метёлка (избыток)

Когда обычная ёмкость корней заполнена, дальнейшая генерация идёт в **избыток**.

1. Появляется карта **«Метёлка»** (уборка паутины).
2. Обычный сбор корней / старт ухода может быть заблокирован, пока избыток не разобран.
3. После Метёлки — награда (монета к сундуку), затем снова доступен обычный цикл.

Порядок на сервере в общих чертах: наполнение корней → правила трансфера → избыток / Метёлка → снова трансферы → запасы → Care.

---

### Дерево растёт вместе с вами

Пять стадий по накопленным миллиметрам:

| Стадия | Порог |
|--------|--------|
| Росток | 0 мм |
| Саженец | 50 мм (5.0 см) |
| Деревце | 200 мм |
| Молодое дерево | 500 мм |
| Могучее дерево | 850 мм+ |

Каждая стадия — отдельный SVG. После ухода дерево растёт в прямом эфире: таймер/счётчик +N мм, смена стадии при пересечении порога.

---

### XP и уровни

За каждую активность ухода:

```
XP_activity = round(100 × T / 25 × Skill)
```

XP цикла — сумма трёх активностей. Уровни и рейтинг (серия / XP / рост мм) живут в модальном окне истории и лидерборда.

---

### Зачем возвращаться

- энергия копится **непрерывно** — есть смысл заглянуть, когда колба/корни готовы
- уход даёт XP, мм и доход
- Метёлка и избыток не дают «забыть» заполненную ёмкость
- серия визитов влияет на эффективную ёмкость запасов
- видимый прогресс дерева и капитала

---

### Как банки становятся партнёрами

Целевая модель (пока не в коде как live OAuth): Росток — игровой слой поверх реального накопительного счёта. Банк даёт API-доступ с разрешения клиента; игра читает баланс вместо демо.

1. Клиент авторизует доступ к счёту (Open Banking / OAuth).
2. Росток показывает реальный баланс — дерево растёт с настоящими накоплениями.
3. Банк получает вовлечённых клиентов и более стабильную ресурсную базу.

> Сейчас в репозитории — **демо-счёт** (email/пароль, стартовый капитал). Интеграция с банком — продуктовая цель.

---

### Зачем это клиентам банка?

- игровой ритуал вместо «забыл про вклад»
- видимый прогресс: дерево, мм, капитал, уровень
- привычка копить без отдельной силы воли

### Зачем это банкам?

- дольше держат деньги на счёте
- ежедневное присутствие в приложении
- лояльность и эмоциональная привязка к бренду

### Старт для игрока

Регистрация → онбординг (демо-счёт 100 000 ₽) → обязательный туториал → основная игра.

## Обзор

pnpm workspace монорепозиторий на TypeScript. Основной продукт — **Росток** (`artifacts/bank-game`). API и экономика — `artifacts/api-server`.

## Технический стек

- **Monorepo**: pnpm workspaces
- **Node.js**: 24
- **TypeScript**: 5.9
- **API framework**: Express 5
- **База данных**: PostgreSQL + raw `pg` pool (игровое состояние); Drizzle ORM (shared lib)
- **Аутентификация**: сессии email + пароль, cookie через `SESSION_SECRET`
- **Валидация**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (из OpenAPI spec)
- **Сборка**: esbuild (CJS bundle)
- **Клиент**: React + Vite (`artifacts/bank-game`)

## Основные команды

- `pnpm run typecheck` — проверка типов по всем пакетам
- `pnpm run build` — typecheck + сборка
- `pnpm --filter @workspace/api-spec run codegen` — регенерация хуков и Zod из OpenAPI
- `pnpm --filter @workspace/db run push` — схема БД (только dev)
- `pnpm --filter @workspace/api-server run dev` — API на :8080
- `pnpm --filter @workspace/bank-game run dev` — клиент (proxy `/api` → `:8080`)

Для Economy v3 в окружении api-server:

```
ENABLE_ECONOMY_V3_ROOTS=true
```

## Архитектура

### Аутентификация

- Собственная сессионная авторизация (email + пароль), cookie-based
- Сессии на api-server; нужен `SESSION_SECRET`
- Vite dev proxy: `/api` → `http://localhost:8080`

### Database (raw SQL, не Drizzle для game state)

Ключевые таблицы (упрощённо):

- `users` — учётные данные, никнейм
- `accounts` — балансы (в т.ч. сейф / активный капитал), якоря начислений
- `game_state` — туториал, XP, уровень, серия, `tree_growth_mm`, флаги сессий
- таблицы / колонки Economy v3 — корни, запасы, циклы Care, Метёлка, vault (миграции в `economy-v3-roots-migrations.ts`)
- `income_history` — журнал начислений

### State flow (v3)

- API-first: состояние в PostgreSQL, клиент синхронизируется через `/api/game/...`
- Непрерывные часы генерации энергии (`T(K)`)
- Цикл ухода: start activity → finish → ack → (×3) → shovel finish/claim/ack
- Награды и мм пишутся на сервере при claim; клиент отыгрывает анимации

### XP / рейтинг

- Вкладки: **История** и **Рейтинг**
- Режимы рейтинга: серия, XP, рост (`tree_growth_mm`)
- Строка: никнейм + уровень

### Визуальная система дерева

- 5 стадий (0–4), отдельные SVG, `STAGE_DIMS`
- `preserveAspectRatio="xMidYMax meet"` — корень у низа контейнера
- Раскладка: `.game-tree-wrap` у линии травы; крона растёт вверх

## Туториал (v3)

Обязателен, пока `tutorial_done = false`.

### Шаги

```
welcome
  → plant-sprout
  → capital-transfer   (energy-explain → drag-vault)
  → intro              (fast-fill / ожидание энергии)
  → v3-root-water | v3-root-sun | v3-root-fertilizer
  → v3-activities-intro → water / sun / fertilizer (+ intro-шаги)
  → «Уход» (карточка завершения этапов)
  → сбор награды
  → complete
```

| Шаг | Что видит игрок |
|-----|-----------------|
| `welcome` | «Ухаживайте за деревом» — план шагов |
| `plant-sprout` | «Посадите росток» — тап по пунктирному овалу |
| `capital-transfer` | сначала «энергия без капитала», затем «перенесите капитал в сундук» |
| `intro` | фиолетовые часы ускорения / «дождитесь формирования энергии» |
| корни | «Соберите энергию из корней» |
| активности | «Пройдите активность» + подсказка под игру |
| после трио | «Отлично! Все три этапа пройдены!» + «Нажмите на кнопку «Уход»» |
| награда | «Соберите награду» — яблоки и монетки |
| `complete` | окно «обучение пройдено» → «Начать играть» |

Компенсация туториала: доход **12% APR** за время капитала в сундуке (₽), без продакшен-мм.

### Ограничения

- UI вне текущего шага заблокирован / пульсирует только нужная цель
- реальный продакшен-цикл не стартует поверх незавершённого туториала случайно
- `api.tutorialComplete()` — при закрытии финального окна
